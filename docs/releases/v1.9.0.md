# Pix8 1.9.0 — paste that floats, and a way out to a sprite pipeline

Pix8 is a 256-color indexed pixel art editor built around VGA-era workflows:
one shared 256-entry palette for the whole document, independent layers,
frame animation, and a GrafX2-style palette editor.

Two themes in this release. **`Ctrl+V` changes meaning** — paste now lands on
the current layer as a floating selection you can drag, the way it does in GIMP
and Aseprite. And Pix8 grows an exit to a real sprite pipeline: **export every
animation frame as its own PNG**, from the app or from a new **command line**.

## ⚠️ `Ctrl+V` does something different now

Paste used to create a new layer. It now pastes onto the **current** layer as a
floating selection: drag it with the Move tool, and it is stamped down when the
selection commits — Deselect, Select All, or starting a new selection.

| Key | Now does |
|---|---|
| `Ctrl+V` | Paste onto the current layer as a floating selection, centered |
| `Ctrl+Shift+V` | The same, at the original coordinates |
| `Ctrl+Alt+V` | **Paste as New Layer** — the old behaviour |

Nothing is lost: the old behaviour is still there on `Ctrl+Alt+V` and in the
Edit menu. The swap is to match GIMP and Aseprite, where pasting onto the
current layer is the plain `Ctrl+V` and pasting as a new layer is the special
case. Pix8 previously had no way to do the former at all.

## New: export animation frames as PNGs

*Export as...* gains **PNG frames (zip)** — one PNG per frame, composited at
document size:

```
fox_idle_1.png … fox_idle_4.png
fox_die.png                       <- single-frame tag, no _n
fox_run_1.png … fox_run_6.png
```

The `_<n>` is dropped when a tag holds one frame, so a one-frame `die` does not
become `fox_die_1.png`. Frames ahead of the first tag fall back to
`<basename>_<n>.png`. Underscores rather than dashes, because that is how
sprite sheet layers are named and these files are headed back into a texture
packer.

## New: a command line

```
pix8 export:frames <source.pix8> <output-folder> [--basename=NAME] [--clean] [--dry-run]
```

The same frames, named identically, written as loose files instead of zipped —
for the loop where you save a `.pix8`, repack a texture atlas, and look at it in
a game. The naming rules and the frame walk live in one module that both the
in-app export and the CLI call, so the two cannot drift apart.

Existing files are overwritten. Files that are *no longer produced* are not:
rename a tag and its old PNGs stay in the folder for a texture packer to find.
The run reports any it did not write, and `--clean` deletes them — matching on
the full `<basename>_` prefix, so one character's export can never touch
another's in a shared atlas folder. `--dry-run` lists without writing, and stays
a true no-op even combined with `--clean`.

`npm link` puts `pix8` on PATH. PNG encoding goes through Node's own zlib, so
JSZip remains the project's only runtime dependency.

## New: a sprite sheet splitter

`tools/split-sprites.mjs` turns a sheet that keeps every sprite as its own layer
into a per-character animated `.pix8` — one frame per layer, grouped into tags
by animation name:

```
node tools/split-sprites.mjs sheet.pix8 player player.pix8
  32x32, 30 frames in 11 tags, 1 layer "player"
    idle          4 frame(s)
    run           6 frame(s)
    ...
```

Canvas size comes from the first frame, with `--size=max` for a character whose
first frame is not representative, and a warning whenever any frame exceeds the
canvas. `--default-tag` names animations that have none in their layer name, and
a frame smaller than the canvas is centred rather than pinned to the corner.

## Fixed in this version

- **Onion skins are no longer baked into exports.** `Renderer.composite()`
  draws them when they are enabled, so exporting with onion skinning on put the
  red/blue ghosts of the neighbouring frames into every frame. **This affected
  GIF export in every previous version.**
- **Playback no longer leaves the whole timeline highlighted.** Every frame the
  playhead passed through was added to the selection and never removed, so
  after one loop the entire run was styled as selected. Stopping used to leave
  two highlighted frames; it now collapses onto the one it landed on.
- **The layers dock no longer flickers during playback.** Each tick emitted two
  events that drive the same listeners, so the layers list was rebuilt twice per
  frame — ten times a second. The duplicate is gone, and the layers dock and
  frame thumbnails now stand down entirely while the playhead runs, since
  neither has anything new to show until it stops.
